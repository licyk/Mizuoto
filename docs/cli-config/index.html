配置与环境变量

Mizuoto 的设置保存在 settings.toml 中，网页界面的设置页、mizuoto config 命令和 MIZUOTO_ 环境变量改的是同一份设置；本页列出全部设置项、环境变量和数据文件夹的结构。

设置的来源与优先级

生效的设置由四层合并而成，后面的覆盖前面的：

  1. 内置默认值；
  2. settings.toml（默认在数据文件夹中）；
  3. 环境变量 MIZUOTO_<GROUP>__<FIELD>；
  4. 嵌入方固定的值（Mizuoto 在另一个程序里运行时才有，见 在 Python 中使用）。

环境变量和固定值只在内存中生效，不会写回 settings.toml，也不能在网页界面或接口中修改。网页界面中被环境变量覆盖的设置标注 由环境变量设置，被嵌入方固定的标注 由运行 Mizuoto 的应用程序设置；mizuoto config set 修改一个被环境变量覆盖的设置时会提示 An environment variable overrides this setting.。

数据文件夹与设置文件

数据文件夹存放设置、数据库、模型、音色和结果。默认位置：

系统位置
Linux$XDG_DATA_HOME/mizuoto，未设置时为 ~/.local/share/mizuoto
macOS~/Library/Application Support/mizuoto
Windows%APPDATA%\mizuoto

用环境变量 MIZUOTO_DATA_DIR 或 mizuoto webui --data-dir <路径> 换到别处。settings.toml 默认在数据文件夹里；MIZUOTO_CONFIG_DIR 或 webui --config-dir 可以把它放到另一个文件夹（数据仍在数据文件夹中）。网页界面 设置 › 关于 显示 数据文件夹 和 设置文件。

想让 mizuoto config、mizuoto speak 等命令与服务器使用同一个数据文件夹，用环境变量最方便：--data-dir 只是 webui 的选项。

文件夹结构

paths.* 设置可以把模型、音色、结果、数据集、实验、项目和缓存分别放到别处；留空表示在数据文件夹里，相对路径也一样（results 即 <数据文件夹>/results，与从哪个目录启动 Mizuoto 无关）。

用命令行查看和修改

  • 键用点分隔，值按 JSON 解析（数字、true/false、列表、对象），解析不了时作为字符串；null 清除可以为空的设置。写入前整体校验，取值超出范围、类型不对或键不存在时报错（退出码 4），文件不变。
  • 字典类的设置可以添加新键：engines.<引擎 id>.<字段>、engines.<引擎 id>.load_options.<选项>、tts.model_aliases.<别名>。mizuoto config set 不检查加载选项的名称和取值；网页界面和接口会按引擎清单检查。
  • config show 和 config get 不显示令牌，只显示 access_token_configured、token_configured 是否已设置；config set 修改令牌后显示 (hidden)。config show 还列出 resolved_paths（留空的文件夹实际使用的路径）、env_overrides（生效的环境变量）和 pinned（嵌入方固定的设置）。
  • 正在运行的服务器约 1 秒内读到文件的改动，打开的网页界面随之刷新；之后在网页界面保存设置时，会在文件当前内容的基础上合并，不会冲掉命令行的改动。文件写坏时服务器日志会警告 Ignored a change to … settings.toml，继续使用原来的设置。server.host、server.port 和证书要在下次启动服务器时生效；修改 engines.<id>.* 会卸载该引擎的模型，下次使用时按新设置加载。
  • 读取 settings.toml 时，Mizuoto 不认识的键会被忽略。

环境变量

mizuoto env vars 列出 Mizuoto 读取的环境变量，以及当前已设置的 MIZUOTO_* 变量：

变量含义
MIZUOTO_DATA_DIR数据文件夹
MIZUOTO_CONFIG_DIR存放 settings.toml 的文件夹，不想放在数据文件夹时使用
MIZUOTO_LOG_LEVEL日志级别：DEBUG、INFO、WARNING 或 ERROR（默认 INFO）
MIZUOTO_<GROUP>__<FIELD>覆盖一个设置，例如 MIZUOTO_SERVER__PORT=8000 或 MIZUOTO_DOWNLOADS__SOURCE=hf-mirror
HF_TOKENHugging Face 访问令牌，下载模型时只发给 huggingface.co，不发给镜像

覆盖设置的规则：

  • 去掉前缀 MIZUOTO_ 后转为小写，__（两个下划线）表示下一级：MIZUOTO_COMPUTE__GPU_JOBS 对应 compute.gpu_jobs，MIZUOTO_ENGINES__QWEN3TTS__DEVICE 对应 engines.qwen3tts.device，MIZUOTO_REMOTE__AGENT__PORT 对应 remote.agent.port。
  • 值能按 JSON 解析就按 JSON 解析（数字、true/false、列表、对象），否则作为字符串；null 或 none 表示空值。
  • 只有名称中含 __ 的 MIZUOTO_* 变量才是设置覆盖。

compute：计算

键默认值说明界面
compute.devices[]Mizuoto 可以使用的设备，如 ["cuda:0"]；为空时使用找到的全部设备—
compute.default_deviceauto引擎的默认设备：auto、cpu、cuda:N（NVIDIA，或 ROCm 上的 AMD）、xpu:N（Intel）或 mps计算 › 默认设备
compute.unload_after_minutes20模型空闲这么久后卸载；0 表示一直保留计算 › 空闲多少分钟后卸载模型（0：从不）
compute.max_resident_models3所有引擎合计同时保持加载的模型数（1–32），超出时先卸载最久没用的空闲模型计算 › 保留在内存中的模型数
compute.vram_reserve_mb1024在请求所需之外保留的空闲显存（MB）：不够时空闲模型（逐部分）让出显存，直到放得下计算 › 保留的空闲显存（MB）
compute.vram_modeauto模型如何使用显存：auto/normal（放得下时整体加载，否则部分加载，其余从内存流式加载）、high（只整体加载）、low（最多一半空闲显存）、none（几乎全部流式加载）计算 › 模型如何使用显存
compute.vram_limit_mb0每块 GPU 最多使用（MB；0：全部）计算 › 每块 GPU 最多使用
compute.ram_reserve_mbnull保留的空闲内存（MB）；低于它时丢弃内存中的权重副本、卸载空闲模型。null：2 GB 与内存十分之一中较大者计算 › 保留的空闲内存
compute.host_copiesauto为 GPU 上模型的权重在内存中保留副本：auto（内存充足时）、on、off计算 › 在内存中保留显存权重的副本
compute.max_pinned_mb0权重的主机副本（流式加载的，或为重新加载而保留的）使用的锁页内存（MB；0：自动）计算 › 主机上的权重使用的锁页内存
compute.async_offload-1流式权重的复制流数量（-1：NVIDIA 和 AMD 上两个，其他为零；0：关闭）；自回归模型从不预取计算 › 复制流数量
compute.oom_retrytrue某一步显存不足时，把更多权重留在内存中重新运行（结果相同）计算 › 显存不足时重试该步骤
compute.oom_fallbackfalse之后允许引擎用更省显存的方式（分块、更小的批次；输出略有不同）计算 › 之后允许更省显存的方式
compute.kv_cachedynamicstatic：Qwen3-TTS 与 CosyVoice 2/3 使用预先分配的键值缓存—
compute.cuda_graphstrue在 NVIDIA 显卡上以 CUDA Graph 运行语言模型的解码步骤（Qwen3-TTS、Fish Speech、CosyVoice 2/3、VoxCPM、GPT-SoVITS、IndexTTS），结果完全一致—
compute.cuda_allocatorautotorch 的 CUDA 显存分配器：native、async（其下不使用 CUDA Graph）、expandable（auto：native）；下次启动时生效—
compute.cpu_allocatorautoCPU 内存分配：tuned、system（auto：Linux + glibc 上为 tuned）；下次启动时生效—
compute.cpu_threadsautoCPU 线程：cores（绑定到物理核心）、off（auto：Linux 上为 cores）；下次启动时生效—
compute.simulate_vram_mb0用于测试：让 CPU 扮演这么大的一块 GPU—
compute.gpu_jobs1一块 GPU 上同时运行的 GPU 任务数（1–16）计算 › 同时运行的 GPU 任务数
compute.inference_jobs1跨所有引擎和设备同时运行的合成任务数（合成、音色转换、语音编辑；1–16），其余任务在队列中按顺序等待。合并为一个微批次运行的请求算一个任务计算 › 同时运行的合成任务
compute.compilefalse用 torch.compile 编译 F5-TTS、CosyVoice、GPT-SoVITS v4/v5 和 IndexTTS 的重型模块；在 GPU 上 VoxCPM 会因此变慢（没有 CUDA 图）；对修改之后加载的模型生效（见 性能与加速）计算 › 编译模型（torch.compile）
compute.attentionauto引擎如何计算注意力：auto（按各模型原本的方式，结果完全相同）、fast（可用的最快后端），或指定后端：sdpa、math、sdpa_flash、sdpa_efficient、sdpa_cudnn、flash、xformers、sage、sage3；某个后端无法处理的调用会回退到下一个；对修改之后加载的模型生效（见 性能与加速）计算 › 注意力
compute.attention_strictfalse所选后端无法计算请求的某一部分时让请求失败，而不是回退计算 › 失败而不是回退
compute.fast[]作用于整个进程的 GPU 提速开关，每一项都会使结果略有不同：tf32、fp16_accumulation、cudnn_benchmark、sdpa_reduced_precision（fp16_accumulation 会使 GPT-SoVITS v2 慢约 5 %）；下次启动时生效计算 › 加速
