接入引擎

以 OmniVoice 为例，讲一个引擎怎样编写和接入：清单与模型文件清单、Engine 与 LoadedEngine 契约、模型句柄、任务类型、错误、共享资源、注册，以及让它与上游保持一致的测试。

Mizuoto 里的一个引擎由放在两处的两样东西组成，外加它的测试：

部分位置由谁读取
清单：变体、能力、参数、选项、目录中的模型、共享资源、许可、训练方法mizuoto/core/engines/manifests/<id>.toml，模型文件清单在 manifests/files/核心（EngineRegistry），不导入引擎
实现：一个 Engine 子类和它的 LoadedEngine，基于 mizuoto.runtime、mizuoto.nn 和 mizuoto.text 构建mizuoto/engines/<id>/，单独发布的则在 packages/native/<id>/运行时，在服务器进程里
测试tests/engines_native/test_<id>_tiny.py、契约套件、scripts/parity/CI，以及你自己

核心只凭清单规划和校验每个请求，然后经由 core/inference 调用实现（见运行时）。本页以 OmniVoice 为例：mizuoto/core/engines/manifests/omnivoice.toml 和 mizuoto/engines/omnivoice/。

flowchart LR
  man["manifests/omnivoice.toml<br/>+ files/omnivoice.files.json"] --> reg["EngineRegistry<br/>校验 · 表单 · 模型目录"]
  reg --> tts["TtsService.plan"]
  tts --> rs["RuntimeService.loaded"]
  rs -- "get_engine('omnivoice')<br/>BUILTIN 或入口点" --> eng["OmniVoiceEngine.load<br/>→ LoadedOmniVoice"]
  eng --> rt["mizuoto.runtime<br/>ops · loading · 句柄"]
  eng --> nn["mizuoto.nn · mizuoto.text<br/>HuBERT · DAC · BPE"]

1. 清单

mizuoto/core/engines/manifests/*.toml 随 mizuoto 包发布；EngineRegistry 读取目录下的每个文件，按 EngineManifest（mizuoto/core/engines/models.py）校验。需要接受许可的引擎，其清单也在 mizuoto 里，所以在它的发行包装上之前，模型目录和许可全文就已经在了。顶层字段：

字段含义
id引擎 id；实现以同一个 id 注册
devices引擎能运行的设备类型（cuda、cpu、mps、xpu）
languages规范语言代码；* 表示任意
[upstream]移植所复现的项目和提交（仅作说明，不是依赖）
ops、internalcall 操作名；内部辅助引擎（ASR），不用于合成
[weights]音色自有微调权重的角色和后缀（GPT-SoVITS：gpt = ".ckpt"、sovits = ".pth"）

变体与能力

一个变体就是一组静态能力；请求在任何任务创建之前就对照它校验：

完整列表是 models.py 里的 Capability。有些能力会改变处理流程：没有 long_text 时 Mizuoto 自己切分文本；batch 且 max_batch > 1 时启用微批处理；stream_audio 的粒度来自 stream_granularity；stream_text_input 允许通过 WebSocket 流式输入文本。变体还可以有 languages、speakers、emotions、inline_tags、instruct_requires 和 weights_version。

参数、选项与加载选项

表模型说明
[params.<通用名>]ParamSpec只能用 CommonParam 里的名字（temperature、top_p、num_steps、speed、seed 等）。target 是引擎自己的名字；default 只是展示引擎的默认值，Mizuoto 从不强加；approximate = true 会在结果里加一条警告；variants 和 streaming 限定适用范围
[options.<名字>]OptionSpec引擎专有选项（engine_options）；未知的选项一律报错；group = "hidden" 不在表单里显示。引擎的 OPTION_SCHEMA 必须与它们完全一致
[load_options.<名字>]OptionSpec模型加载时应用（engines.<id>.load_options，即引擎卡片上的“选项”），如 F5-TTS 的 ode_method、IndexTTS 的 use_torch_compile。它们通过 LoadSpec.options 传给引擎

模型与模型文件清单

files（ModelFiles）还可以有 subdir、into、include、exclude 和 unpack；extra 列出更多仓库；assets 指明共享资源；vram_mb 是随模型显示的目录显存数字（加载从不因它而拒绝）。

增改模型后运行 python scripts/dev.py model-manifests omnivoice。scripts/model_manifests.py 把 Hugging Face 修订版本固定到当前提交，并把每个文件的大小和 SHA-256（LFS 文件取自元数据，小文件下载后计算）写进 manifests/files/<manifest>。下载时据此校验；test_catalogue_models_have_files_manifests 检查目录里的每个模型都有文件清单。

共享资源、许可与训练

  • [[assets]]：一个引擎的多个模型共用的文件（GPT-SoVITS 的编码器和文本前端数据、IndexTTS-2 的 w2v-BERT 等），写法同模型，安装在 <models>/_assets/<engine>/<name>/。模型在 assets 里写明需要哪些；引擎通过 spec.options["assets"]（资源 id → 目录）拿到它们的目录。
  • [licence]：gated = true 时，下载权重和共享资源、合成都要求 engines.<id>.accepted_licence == id@version；file 指向 manifests/licences/ 里的全文；trains_others = false 拒绝把它的输出用作其他引擎的训练数据；notice 显示在结果下方；commercial 用于给输出打标签。
  • [training.<id>]：训练方法，由引擎的 TRAINER 运行；见训练器。

识别模型文件夹

mizuoto model import 只凭文件内容判断引擎和变体：mizuoto/core/models/detect.py 读取配置文件（OmniVoice：config.json 里 model_type == "omnivoice"），引擎的 detect_variant 必须与它一致。

2. 实现

一个引擎是 mizuoto/engines/<id>/ 下的一个包，__init__.py 导出 Engine 子类，各模块只导入分层规则允许的东西：mizuoto.runtime、mizuoto.nn、mizuoto.text、mizuoto.training、mizuoto.core.codes、mizuoto.core.inference.tasks、自己的包，以及 numpy、torch 和文本库；绝不导入另一个引擎。它的模块顶层不导入 torch（test_engine_contract_import_is_light 和 test_manifest_options_match_the_engines 会在没有 torch 的情况下导入引擎模块）：torch 在方法内部导入，类型注解放在 if TYPE_CHECKING: 下。

Engine

成员用途
id引擎 id（与清单和注册表一致）
VERSION实现自己的版本字符串（默认 "1"）。音色缓存按 Mizuoto 的版本区分，而不是这个
OPTION_SCHEMA与清单的 [options] 完全对应的 OptionSpec：类型、默认值、最小值、最大值和可选值都相同（test_manifest_options_match_the_engines）
TRAINER引擎的 mizuoto.training.Trainer 的 "模块:类"，可训练时才有
EXTRAS可选功能：安装说明 → 它提供的模块，如 GPT-SoVITS 的 {"mizuoto[gptsovits-ja]": ("pyopenjtalk",), "mizuoto[gptsovits-ko]": ("mecab", "jamo")}；mizuoto doctor 列出导入不了的那些
detect_variant(model_dir)只凭文件夹里的文件判断变体，不用 torch
load(spec, runtime, ctx)依据 spec（model_id、model_dir、variant、device、dtype、options）构建模型，返回一个 LoadedEngine；用 ctx.progress("loading:<部分>") 汇报，各部分之间调用 ctx.check_cancel()
call(op, payload, ctx)不需要已加载模型的操作

LoadedEngine

一个已加载的模型。它不可重入：任务调度器一次只给它一个请求（engine:<引擎>:<设备> 资源）。

方法必需用途
describe()是返回 Description：采样率、能力、说话人、语言、显存、ignored_params
synthesize(task, ctx)是生成器：每准备好一段就 yield AudioChunk(samples, sample_rate, segment, final)，每一步都调用 ctx.check_cancel()；把实际使用的值记进 ctx.applied，警告用 ctx.warn()
prepare_voice(voice, cache_dir, ctx)把派生的音色状态（提示码、嵌入）写进 cache_dir，以 VoiceCache(files, meta) 返回；之后的请求在 VoiceSpec.cache 里拿到这些文件
convert(task, ctx)、edit(task, ctx)音色转换和语音编辑，同样是生成器；默认抛出 Unsupported
call(op, payload, ctx)清单 ops 里列出的操作（ASR 的 transcribe、Fish Speech 的 codec_encode / codec_decode）
memory_required(task)一个请求在权重之外需要的设备内存字节数；模型管理器会为它腾地方
close()丢弃权重（管理器已经把句柄从设备上移走了）

引擎返回模型自身采样率下、范围在 [-1, 1] 的 float32 单声道音频，从不编码：拼接、归一化、重采样和编码都是核心的事。它收到的是解析好的、确实存在的绝对路径（参考音频是 cache/refs/ 里的 16 位 WAV），从不下载。核心已经对照清单校验过请求，所以引擎只做映射，不做检查。

任务类型

请求和结果都是 mizuoto/core/inference/tasks.py 里的标准库数据类，由 mizuoto.runtime.engine 重新导出：

类型字段
SynthesisTasktext、language、voice、style（instruct、emotion）、params（按 Mizuoto 名称的通用参数）、options（引擎选项）、texts（批处理）、segment / segments、stream、text_stream
VoiceSpecreferences（Reference：audio_path、transcript、language、sample_rate、duration）、preset、description、attributes、weights、cache、voice_id
VoiceConversionTask、SpeechEditTask源音频和音色；音频、其文本和若干 EditSpan
LoadSpec、Description、AudioChunk、VoiceCache、OptionSpecload 收到的、describe 返回的、音频、音色缓存、选项

模型句柄

每个带权重的模块都包进一个 ModelHandle，列在 self.handles 里，模型管理器才能安放它、移走它并报告它的大小：

用 ops.default 搭建模块（不做随机初始化），用 mizuoto.runtime.loading（load_state_dict、严格的 load_into）加载权重，参数保持 nn.Module 创建时的样子。每个随机数都从 ctx.generator_for(device) 或 ctx.rng 取，并按上游的顺序抽取（见运行时）。

用 mizuoto.runtime.accel.attention(q, k, v, site=SITE, …) 计算注意力，不要直接调用 F.scaled_dot_product_attention（架构测试会禁止）：每个调用点声明一次 SITE = accel.Site("<id>.<部分>")，并传入上游传给 SDPA 的参数（causal 就是它的 is_causal）。上游手写注意力的调用点把那段代码作为 reference；只能由参照计算的调用点设为 swappable=False（在分数中加入相对位置的注意力根本不是调用点，仍是手写代码）。调用点按某种结构（单侧填充、因果、窗口）构建掩码时，同时传入 mask_info，让更快的内核也能处理这次调用（加速）。

错误

抛出 EngineError(message, detail, code=codes.…)，错误码取自 mizuoto.core.codes（invalid_input、capability_not_supported、model_missing 等）；把解决问题的命令放进 detail["hint"]。Unsupported(message) 就是 capability_not_supported。核心依据错误码还原领域错误；内存不足和其他异常会自动映射。

4. 测试

tests/engines_native/test_<id>_tiny.py 在临时目录里搭一个与引擎结构相同、权重随机的小模型（配置文件、字节级词表、测试自己写出的 safetensors），在 CPU 上走真实的代码路径：加载、音色提示及其缓存、解码、批处理、可重复的种子、取消。不下载任何权重，所以 CI 每次推送都跑（CPU 版 torch）。test_omnivoice_tiny.py 是一个完整的例子；训练器有 test_<id>_train_tiny.py。

输出不一致时

先看随机数：上游可能在构建模型或准备参考音频时抽过随机数（HuBERT 的层丢弃、IndexTTS 的 w2v-BERT、CosyVoice 3 的声码器噪声），或者是对跨步不同的张量抽的。再看张量形状和内核：SDPA 带不带掩码、掩码的精度、是否连续、CPU 线程数。AGENTS.md §2b 按引擎逐一列出了这类发现。

OmniVoice 实例

mizuoto/engines/omnivoice/（总共约 2900 行）：

模块内容
engine.pyOmniVoiceEngine 和 LoadedOmniVoice：加载、音色提示、迭代解码、长文本分块、解码与后处理
model.py基于 mizuoto.runtime.lm.qwen 解码器的扩散语言模型
audio_tokenizer.pyHiggsAudio v2 分词器：nn/codecs/dac、nn/ssl/hubert、残差码本
audio.py、text.py、duration.py、voice_design.py、lang_map.py按 pydub 的算法去静音和淡入淡出；文本分块与标点；时长估计；由设计属性生成指令；语言名称
train.pyOmniVoiceTrainer：full 和 lora 两种方法

从中可以看到：

  • 加载：OmniVoiceModel(config, ops.default) 由 load_into(model, load_state_dict(folder / "model.safetensors")) 填充，再转成目标精度（GPU 支持 bf16 就用 bf16，否则 fp16；CPU 上 fp32；明确设置的 engines.omnivoice.dtype 优先）；音频分词器同样处理；文本分词器来自 mizuoto.text.tokenize.bpe.load_bpe(folder)；两个句柄。
  • 参数映射：Mizuoto 的通用参数名映射到上游的生成配置（num_steps → num_step、temperature → class_temperature），其余由引擎选项填充。
  • 三种音色模式：有参考音频 → 音色提示；有属性 → 由 instruct_from(attributes) 生成的指令；都没有 → 模型自己的声音。自由文本描述会抛出 capability_not_supported。
  • 音色缓存：prepare_voice 把提示存成 prompt.pt；synthesize 优先用 voice.cache["prompt"]。
  • 随机数：Gumbel 噪声从 ctx.generator_for(self.device) 抽取；HuBERT 的层丢弃抽样（上游在评估模式下也会抽）从 ctx.generator_for("cpu") 抽取。
  • 取消与进度：每个解码步调用 ctx.check_cancel()，之后 ctx.progress("generating", …)。
  • 批处理：设置了 task.texts 时，所有文本放进一批，各自以 segment = task.segment + index 产出。
  • 内存：memory_required 按批中每行估算 logits 所需的工作内存。

OmniVoice 的引擎页面记录了对照结果（在 CPU 上以 fp32 运行时，克隆、设计、自身音色和微调模型都与 0.1 完全相同）以及做到完全一致所需的细节。

清单：一个新引擎要动哪些地方

mizuoto/core/engines/manifests/<id>.toml；运行 dev.py model-manifests <id>；需要接受许可时，把许可全文放进 manifests/licences/。

mizuoto/engines/<id>/（或 packages/native/<id>/）：OPTION_SCHEMA 与清单一致的 Engine 子类、它的 LoadedEngine 和所需的模块；可共用的部分放进 mizuoto/nn 或 mizuoto/runtime。

注册：mizuoto/runtime/engine.py 的 BUILTIN，或 mizuoto.engines 入口点加 DISTRIBUTIONS。mizuoto/core/models/detect.py 能识别它的模型文件夹；可选的包放进 pyproject.toml 的附加依赖和 EXTRAS。

测试：tests/engines_native/test_<id>_tiny.py（单独发行的引擎把它们放在自己包的 tests/ 里，如 packages/native/<pkg>/tests/）；tests/core/test_engines.py::test_registry_lookups 里的引擎 id 列表，以及 tests/engines/test_contract.py 里的 engines 覆盖。

mizuoto model download <id>/<名字>，然后在真实模型上跑契约套件；把移植情况和对照结果记进该引擎的页面（engines-<id>，中英文都要），把它加进侧边栏（meta.json、meta.en.json）和引擎参考的表格；如有新的规则，再记进 AGENTS.md。
