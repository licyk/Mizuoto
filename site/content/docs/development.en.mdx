This section is for people who want to change Mizuoto: fix a bug, add an engine, a training method, a screen or an API route. It describes what the code **is** now, the rules it keeps and why, not how to use it (for that, see the [guides](/docs/guide) and the [command line](/docs/cli)).

## What is authoritative

- **The code** and its tests: when anything else disagrees with them, they win.
- **This site's development pages**: the design as built, the rules and why, one page per area, and one page per
  engine in the [engine reference](/docs/engines) (the upstream behaviour each engine reproduces, its deviations, its
  trainer and its parity result). Read the page for the area you change; a change of design updates it, in both
  languages.
- **`AGENTS.md`** (repository root; `CLAUDE.md` points to it): the short working record for contributors and coding
  agents: a map of the code, the rules that must not break, the workflow, and which page covers what.

## One environment, one process

Mizuoto 0.2 is one Python distribution installed into one environment. Every engine (Qwen3-TTS, F5-TTS, OmniVoice, CosyVoice, GPT-SoVITS, VoxCPM, Fish Speech, IndexTTS and the internal Whisper ASR) is implemented in Mizuoto on its own runtime and runs **in the server's own process**. There is no upstream code, no transformers, no environment per engine and no worker process.

| Distribution | Where | What |
| --- | --- | --- |
| `mizuoto` | `mizuoto/` | The core, the API, the command line, the web UI (its built `dist/` ships in the wheel), the runtime, the building blocks and every engine under a permissive licence |
| `mizuoto-fishspeech` | `packages/native/fishspeech/` | Fish Speech, under the Fish Audio Research License |
| `mizuoto-indextts` | `packages/native/indextts/` | IndexTTS, under the bilibili Model Use License |

The two licence-gated engines are separate distributions only because of their licences. They install into the same environment and register themselves under the Python entry-point group `mizuoto.engines`.

The boundary that decides where code goes is now inside the package: **`mizuoto/core` never imports torch at module level**, and `mizuoto/core/inference` is its only door to model code (`mizuoto.runtime`, `mizuoto.nn`, `mizuoto.engines`, `mizuoto.training`), always imported inside functions. So `mizuoto version`, `mizuoto --help` and the core's own tests load no torch, and a command that never loads a model never imports the runtime. [Architecture](/docs/development-architecture) starts from that rule.

## Conventions that hold everywhere

In short (the full list is [Conventions](/docs/development-conventions)):


- Python ≥ 3.10; ruff and ty unpinned, with `lint.select` written out; line length 180; every function annotated (tests and scripts exempt).
- Models that cross the API boundary derive from `Record` in `mizuoto/core/record.py` (pydantic v2, `json_schema_serialization_defaults_required`).
- Heavy imports go inside functions; a class that annotates with `list[...]` has no method named `list`.
- Native code changes no process-wide state: randomness comes from the request's generators (see [Runtime](/docs/development-runtime#global-state)).
- A new CLI command is also added to `EXPECTED_TREE` in `tests/cli/test_cli.py`.
- Commit and open PRs only when asked.
