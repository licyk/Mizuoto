OpenBMB's tokenizer-free TTS ([OpenBMB/VoxCPM](https://github.com/OpenBMB/VoxCPM), Apache-2.0, code and weights): continuous speech latents generated patch by patch, with no discrete codes. Code: `mizuoto/engines/voxcpm`. Mizuoto 0.1 had no VoxCPM, so the reference is upstream's own package, run behind an adapter in the same Mizuoto stack with the library versions upstream locks (transformers 5.3.0, tokenizers 0.22.2, wetext 0.1.2, inflect 7.5.0). On the CPU with the same seed every component and request is identical to it in bf16 (upstream's default) and in fp32, and both trainers give its weights bit for bit. User-facing details: [Engines in depth](/docs/advanced-engines#voxcpm).

## Variants and files

| Variant | Catalogue model | Parameters | Audio | Voice modes |
| --- | --- | --- | --- | --- |
| `v2` | `voxcpm/2` | 2B | 16 kHz in, 48 kHz out | zero-shot, cloning with a transcript (reference + continuation), cloning without one (reference), design from a description, instructions on a cloned voice |
| `v1_5` | `voxcpm/1.5` | 0.6B | 44.1 kHz | zero-shot, cloning by continuation (transcript needed) |
| `v1` | `voxcpm/0.5b` | 0.5B | 16 kHz | zero-shot, cloning by continuation (transcript needed) |

The generation comes from `config.json`'s `architecture` (missing means `voxcpm`); 1.5 is the first generation with a 44.1 kHz VAE. The model folder holds `config.json`, `model.safetensors` (else `pytorch_model.bin`), `audiovae.pth` (else `audiovae.safetensors`), `tokenizer.json` and `tokenizer_config.json`. A voice's cache holds the VAE latents of the prompt (left-padded) and of the reference (right-padded), as upstream's `build_prompt_cache` makes them.

Precision: `auto` is upstream's choice, the config's bf16 on every device including the CPU, float32 on Apple MPS; `engines.voxcpm.dtype` overrides. The VAE always runs in float32.

## How it works

Text tokens and audio patches share one sequence. Per patch, a **text-semantic language model** (MiniCPM-4 with LongRoPE and a static KV cache) and a shallower **residual acoustic language model** produce two hidden states; a **local DiT** (a bidirectional MiniCPM-4 run as a conditional flow, about 10 Euler steps with classifier-free guidance) predicts the next patch of latents from them and the previous patch; a **local encoder** embeds the patch back into the language model; a **stop head** decides whether to continue. The **AudioVAE**, a DAC-like causal convolutional codec with Snake activations, decodes the latents (v2 with sample-rate conditioning, 16 kHz latents to 48 kHz audio).

| Module | What it is |
| --- | --- |
| `config.py` | `config.json` read as data, with upstream's pydantic defaults |
| `minicpm.py` | MiniCPM-4: RMSNorm, LongRoPE, GQA SDPA, the static KV cache, muP residuals |
| `model.py` | The scalar quantiser, the local encoder, the local DiT (v1 and v2), the CFM's Euler sampler, the prompt sequence, `PatchDecoder` and the generation loop |
| `vae.py` | AudioVAE v1 and v2 (causal convolutions, Snake, rate conditioning) and v2's stateful streaming decoder |
| `text.py` | The tokenizer as transformers 5.3 builds it, upstream's split of multi-character Han tokens, the text normaliser |
| `engine.py` | `VoxCpmEngine`, `LoadedVoxCpm`: precision, voice modes, the voice cache, retries, streaming |
| `train.py`, `sft.py` | `VoxCpmTrainer` (methods `full`, `lora`) and its maths |
| `assets/wetext/` | wetext 0.1.2's FSTs for Chinese (with `remove_erhua`) and English normalisation (7.7 MB) |

Shared: `runtime/ops.py`, `runtime/loading.py` (weight norm folded), `runtime/graphs.py`, `nn/dsp/resample.py` (soxr as librosa calls it; torchaudio's sinc), `nn/dsp/wav.py`, `nn/dsp/tiles.py`, `text/normalize/wetext.py` (its `version="0.1"` steps), `runtime/compile.py`.

## What reproduces upstream

- **Precision.** The model is cast before the checkpoint is copied in, as upstream does, so the LongRoPE tables (built in float32) are rounded to bf16 with it.
- **Attention** is SDPA with `enable_gqa` on contiguous tensors: causal for the prefill, bidirectional in the local modules, and per step against the static cache under an explicit boolean mask. Upstream attends over all of the cache's positions (zeros beyond the current length, masked); Mizuoto attends over the cache's first multiple of 256 past the current length (`minicpm.ATTEND_BLOCK`), mask kept. The masked positions only add exact zeros, and SDPA gives the same bits for any cut at a multiple of 64 (checked at every position up to 3100, bf16 and fp32, on the CPU), so the result is identical and VoxCPM2 runs 1.5 times as fast on the CPU.
- **Randomness.** The CFM's noise is the only draw at inference, one `randn` per patch in the model's dtype. Each attempt draws from a fresh generator seeded with its seed, which is where upstream's `torch.manual_seed` puts the process-wide stream. Without a seed, a 32-bit seed comes from the request's stream (upstream: `torch.seed()`) and is reported in the applied parameters.
- **Bad-case retry.** A non-streamed result with `retry_badcase_ratio_threshold` or more patches per text token is generated again with seed + 1, at most `retry_badcase_max_times` times; the patch cap is `min(tokens × ratio + 10, max_len)`. `applied.retries` counts the regenerations.
- **The prompt.** VoxCPM2 reads the clip with `librosa.load(sr=16000)` (soxr); 0.5B and 1.5 with `torchaudio.load` and `torchaudio.functional.resample`. A continuation prompt is padded to whole patches on the left, a reference on the right. The transcript and the text are joined without a space, as upstream joins them.
- **The text.** Line breaks and runs of blanks become one space, then the text is normalised when asked. VoxCPM2's description or instruction becomes a `(…)` prefix with any parentheses inside removed, as upstream's web demo does; both are joined with `, ` when a request has both.
- **The tokenizer** is what transformers 5.3's `LlamaTokenizer` builds from the vocabulary, ignoring the file's own pipeline: no normaliser, `Metaspace` with `prepend_scheme="always"` and no split, no unknown token in the BPE, and the config's special tokens added in id order (a token missing from the vocabulary gets the next free id, so VoxCPM2's `<|im_end|>` is 73442, not the file's 73440). The raw `tokenizer.json` gives other ids for text with leading blanks or after a special token. Upstream's wrapper then splits multi-character Han tokens into characters; a character outside the vocabulary is `<unk>`.
- **The normaliser** is wetext 0.1.2's: the text stripped before tagging and after each FST, and with `remove_erhua` also text with 儿 and no digit handled. Its FSTs differ from those of wetext 0.0.4 (CosyVoice's asset) and of WeTextProcessing (IndexTTS), so they ship with the engine. Numbers are spelled by `inflect`; Mizuoto's 7.3.1 and upstream's 7.5.0 give the same words on the corpus.
- **Decoding.** VoxCPM2 drops the decoded context patches (the prompt's last `min(3, n)`) from the front; the first generation drops `2 × patch × hop` samples whenever there is any prompt audio, as upstream does whatever the prompt's length. Streaming yields one chunk per patch: VoxCPM2 through the stateful causal decoder, the first generation by decoding the last three patches and keeping the newest.
- **Snake** is the TorchScript function upstream scripts; weight norm is folded with `torch._weight_norm`, the call upstream's hook makes at each forward.

## Deviations

- **Not offered**: denoising the reference with ZipEnhancer (`denoise`; a ModelScope pipeline and a second model, off by default upstream), timestamps (stable-ts), upstream's CUDA `torch.compile` (`optimize`) and vLLM serving.
- **Long text** is split by Mizuoto; upstream does not split.
- **Cloning with a transcript on VoxCPM2** uses the reference *and* the continuation, as upstream's web demo does (`reference_prefix`, on by default). Upstream's Python API adds the reference only when the caller passes `reference_wav_path`.
- **`compute.compile`** wraps the local DiT. On the CPU in bf16 it gains nothing, and its float differences can move where the speech ends (VoxCPM-0.5B: 56 320 against 55 040 samples); off by default.

## Memory and speed

Phases: the VAE encodes a voice prompt and decodes; the model (`kind="sequence"`; the local encoder and DiT `hot`, since they run many times a patch) generates; streaming holds both. If the VAE runs out of memory with `compute.oom_fallback` on, it decodes in tiles of 256 latent frames.

A patch is the DiT's Euler steps (each a guidance pair), the local encoder, the stop head and both language models' steps: some 6 000 small kernels, and three waits for the device (the stop flag and each language model's position copied from a Python integer). `model.PatchDecoder` runs a patch over fixed tensors with one wait, for the stop flag. The language models step before the flag is read (upstream reads it first and stops before stepping); they draw nothing and their caches are dropped when generation ends, so the patches are the same. A full cache raises where upstream's step would.

With `compute.cuda_graphs` (NVIDIA, the model wholly on its device, `compute.compile` off) a patch is one CUDA graph per attention span (a multiple of `ATTEND_BLOCK`), number of steps and guidance value; the DiT's noise is drawn from the graphs' generator, loaded from the request's and written back at each patch. The language models' static caches are then kept with the model while graphs are kept (the memory a request needs anyway) and go when the weights move or the model unloads. The real 0.5B and 1.5 give the same audio with and without graphs, 1.6–1.9 times faster per request.

## Training

Methods `full` and `lora` (`train.py`, the maths in `sft.py`), upstream's `train_voxcpm_finetune.py` with its per-model recipes (`conf/<model>/*.yaml`), which fill any hyperparameter left at 0. No `datasets`, `transformers`, `argbind` or tensorboard. Stages: `prepare` (the clips at the VAE's rate, read as `datasets` reads them: soundfile's float64 and `librosa.resample`'s soxr; their tokens; the `max_batch_tokens` filter), `train`, `export`.

- **Draws in upstream's order**, from private generators seeded 42 (upstream's `Accelerator` seeds every generator with 42): the construction's default initialisations replayed (the VAE, then the model, then LoRA's `A` with Kaiming's initialisation, whose values are kept; the checkpoint replaces the rest); per loader pass the base seed and the sampler's seed; per forward the CFM's masks, condition noise (drawn even at scale 0), `r`, `t` and `z`, and LoRA's dropout masks. On a CPU one generator serves everything, as upstream's default generator does; on CUDA the forward's draws come from a device generator.
- **Precision.** On CUDA, as upstream: float32 weights under bf16 autocast with a gradient scaler. Elsewhere float32 throughout: upstream cannot train off CUDA with its configurations (its forward casts the inputs to the config's bf16 while the weights stay float32), so its CPU reference is upstream with a `config.json` that says float32.
- **Kept as upstream**: every clip padded to whole patches on the right; the stop label on the last patch and the loss over audio positions; each micro-batch's loss divided by the accumulation; gradients clipped at 1e9 when clipping is off; the learning rate logged is the next step's.
- **The export.** Full: `model.safetensors` (float32, upstream's keys) beside the base model's config, VAE and tokenizer. LoRA: the base weights (hard-linked where the file system allows) with `lora_weights.safetensors` and `lora_config.json`, applied when the engine loads, as upstream's `VoxCPM(lora_weights_path=…)` does; upstream never merges them. Without a 3–15 s clip the preview is spoken zero-shot.
- `training.memory`: gradient checkpointing over the MiniCPM layers, the local encoder's and the DiT's gives identical results (LoRA dropout and CFM draws replayed); the VAE's decoder stays off the device; for LoRA, `low` stores the frozen linear weights in the autocast dtype (CUDA) and `lowest` streams them from RAM (identical on the CPU).

## Parity

- **Components**, every model in bf16 and fp32: the tokenizer and the normaliser on 420 texts, the VAE's latents and decoding; then whole requests in every mode (zero-shot and cloning in English and Chinese, reference only, continuation only, design, a cloned voice with an instruction, normalisation, a forced retry, streaming with and without a voice, chunk lengths included). All identical.
- **Through the stack**, 27 cases (every voice mode, normalisation, a forced retry, streaming, several segments, other steps and guidance, fp32 through `engines.voxcpm.dtype`): all identical in audio and behaviour (applied parameters, warnings, voice mode, segments, streamed chunk lengths).
- **Training**: VoxCPM-0.5B full, VoxCPM-0.5B LoRA and VoxCPM2 LoRA are identical to upstream's script at every step (both losses, the gradient norm, the learning rate), and so are the saved weights. Each export speaks identically when upstream loads it and when Mizuoto does.
- The contract suite passes (18 tests across the three models).

## Limitations

- No reference denoising and no timestamps.
- On CUDA the first request in a process decodes its latents (which are identical) with slightly different bits from later requests; later requests repeat each other exactly.
- VoxCPM2's full fine-tune needs about 40 GB of memory.
