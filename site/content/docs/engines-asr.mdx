Mizuoto 自己的语音识别：Whisper large-v3-turbo（[openai/whisper](https://github.com/openai/whisper)；权重 MIT），用于转写参考音频和音色、准备数据集，以及计算契约套件的词错误率。代码：`mizuoto/engines/asr`。它不作为合成模型提供。它完全复现 Mizuoto 0.1 运行的东西，即 transformers 4.57.3 的 `pipeline("automatic-speech-recognition")`，给出与 0.1 逐 token 相同的转写结果，在 CPU 上用时约为一半。面向用户的说明见[引擎详解](/docs/advanced-engines)。

## 变体与文件

只有一个变体 `whisper`（目录模型 `asr/whisper-large-v3-turbo`）；模型按 `config.json` 构建，所以同样格式的其他 Whisper 尺寸也能加载。模型目录包含 `config.json`、`generation_config.json`、`model.safetensors`（或 `pytorch_model.bin`）、`preprocessor_config.json`、`tokenizer.json` 和 `tokenizer_config.json`。

引擎只响应一个操作 `call("transcribe", {"path", "language", "options"})`，返回 `{text, language, segments, duration}`。`AsrService` 为它持有一把锁，把设置 `tts.asr_beams`（默认 5）作为 `beam_size` 传入，并按音频的 SHA-256、模型和这个束宽缓存转写结果。

精度：在支持 bf16 的 CUDA GPU 上用 bf16（否则 fp16），其他设备用 fp32；`engines.asr.dtype` 可覆盖。

## 工作原理

0.1 调用流水线时传入 `chunk_length_s=30, batch_size=4, return_timestamps=True`，任务和语言作为生成参数。引擎的做法相同：

1. 按 soundfile 的方式读取 WAV（各声道取平均），用 soxr（其默认的 HQ）重采样到 16 kHz。
2. 没有指定语言时，在前 30 秒上识别语言（解码器在语言 token 上走一步）。
3. 音频切成 30 秒的窗口，两侧各重叠 5 秒；每个窗口的特征按 `WhisperFeatureExtractor` 的方式计算；每次 `generate` 调用处理四个窗口。
4. `generate` 带时间戳解码每个窗口，用 5 束的束搜索，并在窗口内运行 Whisper 的 seek 循环。
5. 流水线的 `_decode_asr` 把各窗口的 token 合并成文本和带时间戳的分段。

| 模块 | 内容 |
| --- | --- |
| `engine.py` | 0.1 的流水线：读取、重采样、语言识别、窗口、`generate`、合并 |
| `model.py` | 按 transformers 4.57.3 的计算方式实现的 `WhisperForConditionalGeneration`（SDPA 路径、编码器的数值截断、交叉注意力缓存） |
| `decoding.py` | 生成设置、按 transformers 顺序排列的 logits 处理器、向量化的束搜索、贪心解码、seek 循环 |
| `text.py` | 按 `WhisperTokenizerFast` 的方式解码、语言 id、窗口边界、`decode_asr` |

共享模块：`nn/dsp/mel.py`（`hf_whisper_filters`、`hf_whisper_log_mel`）、`nn/dsp/wav.py`。

## 与上游一致的做法

- **5 束。** 流水线的默认生成配置（`num_beams=5`）优先于模型的贪心默认值，所以无论 `beam_size` 怎么设，0.1 总是用 5 束解码；选项 `beam_size` 为 1 时保持这 5 束，更大的值则设定束数。0.1 从不传这个选项；Mizuoto 传入 `tts.asr_beams`，默认值 5 得到与 0.1 相同的转写。束搜索是 transformers 4.57 向量化的 `_beam_search`（先 log-softmax，再经处理器，`2 × beams` 个候选）。
- **每个窗口内的 seek 循环。** 每个窗口都补齐到 30 秒；以一对时间戳结束的解码会从该时间戳重新解码（特征平移，后面补零），时间戳对之后的 token 被丢弃。`_decode_asr` 为重新开始的时间戳重新定基，并合并重叠的窗口。
- **特征**来自 transformers 的 `WhisperFeatureExtractor`，使用它自己的 float64 slaney 滤波器组和转置后的乘法，而不是 openai-whisper 的 log-mel。Turbo 的 `tokenizer_config.json` 设置了 `clean_up_tokenization_spaces`（" ." 变成 "."），按分段应用。
- **注意力**：先投影查询再乘以 `head_dim ** -0.5`，SDPA 使用 `scale=1`，q、k、v 都是连续张量；解码器在多 token 提示上为无掩码的因果注意力，每个新 token 不加掩码，缓存按拼接增长。

## 有意的差异

- **模型独立实现。** CosyVoice 的语音分词器里也有一个 Whisper 编码器，但那里用的是 openai 的注意力（q 和 k 各乘以 d^-¼，带掩码），是另一种计算，所以两者不共用。
- **精确的捷径**：只有一个窗口时复用语言识别时的编码器输出；所有束的行逐位相同时不重排交叉注意力缓存。两者都不改变任何 token。

## 显存

每次转写一个阶段：整个模型，解码器标为 `hot`（它按 token 和束运行），`kind="sequence"`。开启 `compute.oom_fallback` 时，显存不足的转写改为一次解码一个 30 秒窗口而不是四个；这是另一种批形状，所以在罕见的并列情况下转写结果可能不同。

## 对照结果

在 CPU 上以 fp32 运行，转写结果与 0.1 完全相同：在 57 段语料音频（自动识别或指定语言）和 6 段 50–124 秒的音频上，文本、分段、语言以及每个窗口的 token 都相同；模块层面还包括特征和 `_decode_asr`（3000 个随机生成的窗口）。完整链路中需要转写参考音频的对照用例（一个 Qwen3-TTS 克隆和一个 CosyVoice 2 克隆）也完全相同，所以契约套件的词错误率不变。

在完整链路中，`scripts/parity/cases/asr.jsonl`（七段 4–120 秒的音频，英文、中文和混合，自动识别或指定语言）在 CPU 上以 fp32 运行和在 GPU 上（RTX 3090，2026-10-19）运行，都给出与 0.1 完全相同的转写：语言、文本以及每个分段的时间戳。

## Paraformer（中文）

`paraformer` 变体（模型目录中的 `asr/paraformer-zh`，权重为 Apache-2.0）就是 FunASR 的 `AutoModel(model=paraformer-large, vad_model=fsmn-vad, punc_model=ct-punc).generate(input=path)`，也就是 GPT-SoVITS 的 `tools/asr/funasr_asr.py` 用于中文的“达摩 ASR”：普通话夹带英文单词，带标点，数字写成汉字。代码在 `mizuoto/engines/asr/paraformer`，移植自 FunASR 1.4.21（MIT）。设置 `tts.asr_model_zh = "asr/paraformer-zh"` 后，下载完成即用于语言为中文的音频（`AsrService.model_for`）；其他语言仍用 Whisper。

**文件。** 模型文件夹就是识别模型的 ModelScope 仓库（`model.pt`、`config.yaml`、`am.mvn`、`tokens.json`），VAD 在 `vad/`，标点模型在 `punc/`，各自固定到其提交；三者都在 `mizuoto-model` 镜像上。`AsrEngine` 按文件夹区分变体（`config.yaml` 写明 `Paraformer`，旁边有 `vad/` 和 `punc/`）。

| 模块 | 内容 |
| --- | --- |
| `paraformer/engine.py` | `inference_with_vad` 在 CPU 上的流程：读取、重采样、VAD、逐段识别、拼接、加标点 |
| `paraformer/model.py` | `WavFrontend`（Kaldi fbank、LFR 7/6、CMVN）、`SANMEncoder`（50 层）、`CifPredictorV2`、`ParaformerSANMDecoder`、贪心解码 |
| `paraformer/sanm.py` | SAN-M 层（带 FSMN 记忆块的注意力），识别模型和标点模型共用 |
| `paraformer/vad.py` | FSMN-VAD：`WavFrontendOnline`、FSMN，以及文件推理驱动下的流式状态机 |
| `paraformer/punc.py` | CT-Transformer：分词、带延续的小句、标点规则 |
| `paraformer/text.py` | `sentence_postprocess`（词元转文本、英文单词、缩写）和 `_join_vad_texts` |

**与上游一致之处。**
- 音频按 `torchaudio.load` 的方式读取，用 `torchaudio.transforms.Resample` 重采样（`nn/dsp/resample.Resample`）。
- FSMN-VAD 的分段与 FunASR 1.4.21 相同：按 60 秒分块，前端保留的样本、LFR 上下文、FSMN 的记忆和状态机都跨块延续；动态静音表取代配置中的结束静音（先 2 秒，在语音中跨过块边界后为 0.2 秒）和语音阈值（0.5）；超过 60 秒的语音在 60 秒处切开。
- 每段单独识别，从短到长，与 FunASR 在 CPU 上的做法相同（`batch_size = 0`）；特征带 `dither` 1.0（Paraformer 前端的默认值）。
- 随机数：上游的 dither 取自 torch 的全局生成器，而它的层堆叠（`MultiSequential`）每次前向都为每层抽取一个均匀随机数，用于推理时不起作用的层丢弃。两者都会推进下一段 dither 所用的生成器；移植版按同样的顺序从同一个生成器抽取两者。
- 文本：去掉特殊词元，拼合英文子词，连续的单字母合成一个大写词；各段文本拼接时汉字之间不加空格；CT-Transformer 以 20 个词为一个小句，把每个小句最后一个句末标点之后的词带到下一个小句，并遵循它的规则（小句开头的 ASCII 词前加空格、句号后首字母大写、末尾补 `。`）。

**有意的差异。**
- **dither 的生成器每次转写都以 0 为种子。** 上游的全局生成器停在其进程上一次留下的位置（FunASR 只在构建模型时设一次种子，构建模型又会从中抽取），所以上游对同一段音频每次的识别结果都可能不同。这里的转写结果等于上游在 `generate` 前生成器处于种子 0 时的结果，且每次都相同（转写结果按音频缓存）。
- **在 GPU 上同样逐段识别。** 上游在 GPU 上会把最长 300 秒的分段补齐后成批识别，这会改变结果；这里在 GPU 上沿用 CPU 的顺序。GPU 上的结果与 CPU 不逐位相同（在 RTX 3060 上，16 段音频中 14 段相同，两段嘈杂的合成音频相差几个字）。

**显存。** 三个句柄，各占一个阶段：VAD（2 MB）处理整段音频，识别模型（880 MB）逐段运行，标点模型（290 MB，主要是 272,727 词的嵌入表）处理文本；在任何设备上都用 float32。在 RTX 3060 上一次转写的 torch 分配峰值为 1.1 GB（模型目录中的 `vram_mb` 为 1,200）。

**对照结果。** 在 CPU 上以 fp32（8 线程）与 FunASR 1.4.21 对照 16 段音频（12 段 3–7 秒，来自八个引擎；4 段 60–124 秒，其中两段中英混合）：每份转写和每个 VAD 分段都相同；模块层面的特征、编码器、预测器、解码器、VAD 每块的得分（另有 11 个边界情况：静音、噪声、短于 0.5 秒的音频、恰为或接近 60 秒整数倍的音频）以及标点模型的 logits（32 段文本，包括小句延续）都逐位相同；文本后处理在 14,000 组随机词元上相同。工作区为 `experiment/paraformer`。

## 限制

- 语音识别在 Mizuoto 内部使用，不作为合成模型提供，也不出现在 `GET /v1/models` 中。
- 显存不足时的回退方式在罕见的并列情况下可能改变转写结果。
