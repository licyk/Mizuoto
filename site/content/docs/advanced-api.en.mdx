The server `mizuoto webui` starts serves the web UI and an HTTP API. The web UI does everything through this API, so scripts and other programs can do the same things.

## Addresses and documentation

| What | Address |
| --- | --- |
| REST API | `http://127.0.0.1:7869/api/v1/...` |
| Interactive documentation (Swagger UI) | `http://127.0.0.1:7869/docs` |
| OpenAPI schema | `http://127.0.0.1:7869/openapi.json` |
| Events (socket.io) | `http://127.0.0.1:7869/ws`, socket.io path `/ws/socket.io` |
| Streaming synthesis (WebSocket) | `ws://127.0.0.1:7869/api/v1/tts/stream` |
| OpenAI-compatible API | `http://127.0.0.1:7869/v1/audio/speech`, `/v1/models` |

Use the port the server actually started on (7869 by default; the next one when it is taken, see [Command line overview](/docs/cli)). With `mizuoto webui --api-prefix /voice`, every address above (the API, the documentation, the socket and the web UI) moves under that prefix, for example `http://127.0.0.1:7869/voice/api/v1/...` and `http://127.0.0.1:7869/voice/v1/audio/speech`.

The OpenAPI schema also lists the socket's event types, so a client's types can be generated from it.

## Resources

Every REST route is under `/api/v1`:

| Group | Main routes | Purpose |
| --- | --- | --- |
| app | `GET /app/version`, `GET /app/health`, `GET /app/meta` | Version, health check (no token needed), first-run information and the torch version |
| settings | `GET /settings`, `PATCH /settings` | Read the settings (the token only as set or not); deep-merge part of them |
| compute | `GET /compute/info`, `GET /compute/usage`, `POST /compute/release` | Devices, memory use, freeing idle GPU memory |
| engines | `GET /engines`, `GET`/`PATCH /engines/{id}`, `GET`/`POST`/`DELETE /engines/{id}/licence`, `GET /engines/{id}/doctor` | Engine state (available or what is missing) and configuration, licences, one engine's checks |
| runtime | `GET /runtime`, `POST /runtime/unload`, `GET /runtime/doctor` | The loaded models, unloading them, the checks of `mizuoto doctor` |
| models | `GET /models`, `POST /models/download`, `GET`/`DELETE /models/{engine}/{name}`, `POST .../verify`, `GET .../speakers` | Catalogue, downloads, verification, deletion |
| assets | `GET /assets`, `POST /assets/download`, `DELETE /assets/{engine}/{name}` | Shared files |
| voices | `GET`/`POST /voices`, `GET`/`PATCH`/`DELETE /voices/{id}`, `.../references`, `.../fit`, `.../prepare`, `.../export`, `PUT /voices/import` | The voice library |
| audio | `PUT /audio/files`, `GET /audio/files/{id}`, `.../content`, `POST /audio/transcribe` | Uploading audio, speech recognition |
| tts | `POST /tts/plan`, `POST /tts/speak`, `POST /tts/convert`, `POST /tts/edit`, `GET /tts/models/{engine}/{name}/spec`, WS `/tts/stream` | Synthesis, conversion, editing, what a model takes |
| outputs | `GET /outputs`, `GET`/`PATCH /outputs/{id}`, `.../content`, `.../rerun`, `POST /outputs/delete`, `POST /outputs/zip` | Results |
| presets | `GET`/`POST /presets`, `PATCH`/`DELETE /presets/{id}`, `POST .../default` | Parameter presets |
| datasets | `GET`/`POST /datasets`, `.../files`, `.../import`, `.../prepare`, `.../report`, `.../rows` | Training datasets |
| train | `GET /train/methods`, `GET`/`POST /train/experiments`, `POST .../{engine}/{name}/run`, `GET .../metrics` | Experiments and training |
| projects | `GET`/`POST /projects`, `.../script`, `.../render`, `.../export` | Projects (long-form reading) |
| remote | `GET /remote/hosts`, `PUT`/`DELETE /remote/hosts/{name}`, `PUT /remote/engines/{id}` | Remote hosts, see [Remote hosts](/docs/advanced-remote) |
| jobs | `GET /jobs`, `GET /jobs/{id}`, `GET .../log`, `POST .../cancel`, `.../retry`, `.../run-anyway`, `DELETE` | Jobs |

`/docs` and `/openapi.json` describe every field.

### The same as the command line

Each operation is one method of the core; the API and the command line only parse, call it and print the result. So the `mizuoto … --json` of a listing or a query prints the JSON its route returns, for example `mizuoto model list --json` and `GET /api/v1/models`. The exception is `mizuoto speak --json`, which prints `{"job": …, "outputs": […]}`: the job plus the output records.

### Loaded models and the doctor

| Route | Answer |
| --- | --- |
| `GET /api/v1/runtime` | `RuntimeStatus`: `torch` (its version, or `null`), `models` (each loaded model's `model_id`, `engine`, `device`, `bytes`, `last_used`, `busy`, `remote`) and `engines` (each engine's `device`, `state`, `current_request`, `last_error`) |
| `POST /api/v1/runtime/unload` | Body `{"model": "qwen3tts/1.7b-base"}` unloads that model (404 when it is not loaded); `{"model": null}` unloads every model not in use. Answers the new `RuntimeStatus` |
| `GET /api/v1/runtime/doctor` | `DoctorReport`: `torch`, `torch_build`, `recommended_build`, `install_command` and `findings` (`level` `ok` / `warning` / `error`, `engine`, `check`, `message`, `fix`) |

`GET /api/v1/engines/{id}/doctor` gives the findings for one engine. The models live in the server's process, so these routes describe that process.

## Errors

An error answers with its HTTP status and one shape:

```json
{"code": "not_found", "message": "Unknown model: nope/x", "detail": {"kind": "model", "id": "nope/x", "hint": "mizuoto model list"}}
```

`detail` depends on the error; `detail.hint`, when present, is a command or a note that fixes it. A request body that does not parse (a missing field, a wrong type) is FastAPI's 422 with `{"detail": [...]}`.

| `code` | HTTP | CLI exit code | Meaning |
| --- | --- | --- | --- |
| `internal_error` | 500 | 1 | An unclassified internal error |
| `not_found` | 404 | 2 | A model, voice, job, output or engine is unknown |
| `conflict`, `busy` | 409 | 3 | A name clash, or a clash with an operation in progress |
| `invalid_input`, `invalid_path` | 400 | 4 | Input that does not validate; a path outside its allowed root |
| `capability_not_supported`, `parameter_not_supported`, `parameter_out_of_range`, `reference_invalid`, `language_not_supported` | 422 | 4 | The model cannot do it, does not take the parameter or the value is out of range, the reference clip is unusable, the language is not spoken |
| `not_local` | 403 | 4 | Works only in a browser on the server machine |
| `licence_not_accepted` | 403 | 5 | The engine's licence is not accepted yet |
| `model_missing`, `engine_not_installed`, `asset_missing` | 409 | 7 | A model is not downloaded, a package the engine needs is not installed (torch, `mizuoto-fishspeech`, `mizuoto-indextts`; `detail.missing` lists them), a shared file is missing |
| `device_unavailable` | 409 | 8 | A device is missing or unusable |
| `compute_unavailable` | 503 | 9 | No usable device, or not enough GPU memory |
| `worker_failed` | 502 | 10 | A training stage's process or a remote agent died or stopped answering |
| `engine_error` | 500 | 10 | An engine raised an exception |
| `timeout` | 504 | 11 | A time limit passed (for example `wait=true`) |
| `download_failed` | 502 | 12 | A download failed from every source |
| `remote_unavailable` | 502 | 14 | A remote host cannot be reached, refused the token or speaks another protocol |
| `cancelled` | 499 | 130 | Cancelled |

Access control has three refusals of its own: `bad_host` (400), `bad_origin` (403) and `auth_required` (401).

## Access control

Each request passes three checks (`mizuoto/api/security.py`):

1. **The Host header.** While the server is bound to a loopback address (`127.0.0.1` by default), `Host` must be `localhost`, `127.0.0.1`, `::1`, the bound address, or a name the embedding application added with `extra_hosts` / `allow_host()`; anything else is 400 `bad_host`. This blocks DNS rebinding. Bound to a non-loopback address (such as `0.0.0.0`), the server does not check `Host`.
2. **The origin.** A state-changing request (anything but `GET`, `HEAD` and `OPTIONS`) or a WebSocket that carries an `Origin` must come from the page's own origin or one listed in `server.allowed_origins`, else 403 `bad_origin`; without an `Origin`, a `Sec-Fetch-Site` that says cross-site is refused too. curl, Python and other non-browser clients send neither header and are not affected. A non-empty `server.allowed_origins` also turns on CORS for those origins.
3. **The access token.** With `server.access_token` set, every request under `/api/`, `/ws/`, `/v1/`, `/openapi.json` and `/docs` must carry it, else 401 `auth_required`. The only exception is `GET /api/v1/app/health`. Give the token in any of these ways:

| Way | Example |
| --- | --- |
| Bearer header | `Authorization: Bearer <token>` |
| Cookie | `mizuoto_token=<token>` |
| Query parameter | `?token=<token>` (for a browser WebSocket, which cannot add headers) |
| socket.io connection | `auth={"token": "<token>"}` |

```bash
mizuoto config set server.access_token "a long random string"
```

On a 401 the web UI shows the **Access token** dialog and asks for it once.

<Callout type="warn" title="Opening the server to other machines">
Bound with `--host 0.0.0.0`, the server logs that other machines can reach it, but it does not require a token. The API can delete files, download models and read audio on the server: set an access token, or put the server behind a firewall, a VPN or a reverse proxy with authentication.
</Callout>

### Routes for the server machine only

These routes read or write anywhere on the server's disk, so they answer only a **browser on the server machine** (a loopback client that addressed a loopback host name); anything else gets 403 `not_local`. A request forwarded through a tunnel or a reverse proxy on the same machine does not count as local.

| Route | Purpose |
| --- | --- |
| `GET /audio/browse`, `POST /audio/files/paths` | Browse and register audio files on the server |
| `POST /models/identify`, `POST /models/import` | Identify and import a model folder on the server |
| `POST /voices/{id}/weights` | Add a voice's fine-tuned weights from server paths |
| `POST /datasets/{id}/import` | Import a folder on the server into a dataset |
| `POST /outputs/{id}/reveal` | Show a result in the file manager |
| `POST /engines/{id}/ops/{op}` | Engine-specific operations (their payload may name server files) |

Browsed and registered paths must also lie inside `paths.browse_roots` (empty: the home folder, the data folder and every drive or volume). Remote clients upload instead: `PUT /audio/files`, or weights role by role with `PUT /voices/{id}/weights/{engine}/{role}`.

## Jobs

Long operations (synthesis, downloads, training, project renders…) return a job rather than waiting for it:

```json
{"id": "j1a13058b6acbeab2259", "kind": "speak", "state": "queued", "progress": null, "result": null, "error": null, ...}
```

`state` goes through `queued`, `waiting` (for a GPU, the engine or another resource; `waiting_for` says which) and `running`, and ends `completed`, `failed`, `cancelled` or `interrupted` (the server stopped while it ran). A finished job has its `result`; a failed one has an `error` with `code`, `message` and `detail`.

| Operation | Route |
| --- | --- |
| Read | `GET /api/v1/jobs/{id}`; a list: `GET /api/v1/jobs?state=active` |
| Log | `GET /api/v1/jobs/{id}/log?offset=0` (returns `lines` and `next_offset`, where the next read starts) |
| Cancel | `POST /api/v1/jobs/{id}/cancel` |
| Retry | `POST /api/v1/jobs/{id}/retry` (failed, cancelled or interrupted jobs) |
| Run without queueing | `POST /api/v1/jobs/{id}/run-anyway` (a job waiting for the GPU, when the memory suffices) |

A synthesis can wait for its result: `POST /api/v1/tts/speak?wait=true&timeout=600` answers with the finished job; `result.output_id` (and `result.output_ids` for a batch) is the result's id. When the job is still running after `timeout` seconds (600 by default, at most 3600) the answer is 504 `timeout` with the job in `detail.job_id`; it goes on, and you read it as usual.

Download the audio with `GET /api/v1/outputs/{id}/content`; `GET /api/v1/outputs/{id}` returns its parameters, duration, sample rate and timings.

Instead of polling, follow `job_updated` among the [events](#events).

## Examples

### Speak and download

<Tabs items={["curl", "Python"]}>
<Tab value="curl">

```bash
BASE=http://127.0.0.1:7869
AUTH="Authorization: Bearer $MIZUOTO_TOKEN"   # leave out when no token is set

job=$(curl -s -H "$AUTH" -H "Content-Type: application/json" \
  "$BASE/api/v1/tts/speak?wait=true" \
  -d '{"model": "qwen3tts/1.7b-custom-voice", "text": "Hello, and welcome to Mizuoto.", "voice_spec": {"preset": "vivian"}, "style": {"instruct": "Cheerful"}}')
id=$(echo "$job" | jq -r .result.output_id)
curl -s -H "$AUTH" "$BASE/api/v1/outputs/$id/content" -o hello.wav
```

</Tab>
<Tab value="Python">

```python
import httpx

client = httpx.Client(base_url="http://127.0.0.1:7869/api/v1", headers={"Authorization": "Bearer <token>"}, timeout=None)

req = {
    "model": "qwen3tts/1.7b-custom-voice",
    "text": "Hello, and welcome to Mizuoto.",
    "voice_spec": {"preset": "vivian"},
    "params": {"seed": 42},
    "output": {"format": "mp3"},
}
job = client.post("/tts/speak", params={"wait": True}, json=req).raise_for_status().json()
if job["state"] != "completed":
    raise RuntimeError(job["error"])
audio = client.get(f"/outputs/{job['result']['output_id']}/content").content
open("hello.mp3", "wb").write(audio)
```

The body is a `SpeakRequest`. Its main fields (`/docs` has all of them):

| Field | Meaning |
| --- | --- |
| `model` | `<engine>/<model>`, such as `cosyvoice/cosyvoice3-0.5b` |
| `text` / `texts` | The text; `texts` is a batch, one result per text (models that take batches) |
| `language` | `zh`, `en`… or `auto` |
| `voice` | A library voice's id or slug |
| `voice_spec` | A voice given with the request, in one way only: `references` (`[{"audio_id" or "path", "transcript"}]`), `preset`, `description` / `attributes` (a `consent` field is ignored) |
| `style` | `instruct` (an instruction), `emotion` (`audio_id` / `path`, `vector`, `text`, `strength`) |
| `params` | Common parameters: `temperature`, `top_p`, `top_k`, `speed`, `seed`, `segment_silence_ms`… |
| `engine_options` | Engine-specific options |
| `output` | `format` (`wav`, `flac`, `mp3`, `ogg`, `m4a`), `sample_rate`, `normalize`, `name` |
| `segmentation` | `engine` (default) or `mizuoto`: who splits long text |
| `strict` | Refuse parameters the model does not take; unset: `tts.strict_params` |

With neither `voice` nor `voice_spec`, the model speaks in its own voice (if it has one). To check a request without running it, `POST /api/v1/tts/plan` returns the segments, the parameters that apply and the warnings. A top-level field the request does not have is ignored, so that a client sending a newer version's field keeps working, and named in the warnings ("Ignored fields the request does not have: …"): engine options go in `engine_options`, and `options` there would be ignored. A conversion or an edit logs such fields.

### Upload a clip and clone it

The body of `PUT /api/v1/audio/files` is the file itself (not multipart); the `name` query parameter names it. The `id` it returns is a reference's `audio_id`:

<Tabs items={["curl", "Python"]}>
<Tab value="curl">

```bash
audio_id=$(curl -s -H "$AUTH" -X PUT --data-binary @ref.wav \
  "$BASE/api/v1/audio/files?name=ref.wav" | jq -r .id)

curl -s -H "$AUTH" -H "Content-Type: application/json" "$BASE/api/v1/tts/speak?wait=true" -d @- <<EOF
{"model": "qwen3tts/1.7b-base", "text": "This is the cloned voice.",
 "voice_spec": {"references": [{"audio_id": "$audio_id", "transcript": "What the clip says."}]}}
EOF
```

</Tab>
<Tab value="Python">

```python
with open("ref.wav", "rb") as f:
    uploaded = client.put("/audio/files", params={"name": "ref.wav"}, content=f.read()).raise_for_status().json()

req = {
    "model": "qwen3tts/1.7b-base",
    "text": "This is the cloned voice.",
    "voice_spec": {"references": [{"audio_id": uploaded["id"], "transcript": "What the clip says."}]},
}
job = client.post("/tts/speak", params={"wait": True}, json=req).raise_for_status().json()
```

</Tab>
</Tabs>

Without a `transcript`, speech recognition fills it in when `tts.auto_transcribe` is on and the recognition model is downloaded; otherwise the model must clone without one. To keep the voice, add it to the library (`POST /api/v1/voices`) and name it with `"voice": "<id>"`.

## Events

The server pushes events over socket.io at `/ws` (socket.io path `/ws/socket.io`). Traffic is server to client only: every operation goes through REST, REST is the truth, and events only tell you when to refresh.

| Event | Payload |
| --- | --- |
| `job_updated` | `job`: the job's state, progress and download speed |
| `job_log` | `job_id`, `offset`, `lines` (at most 50; read the rest over REST) |
| `jobs_cleared` | `ids` |
| `outputs_added` / `outputs_removed` | `ids` (and `job_id` when added) |
| `voices_changed`, `presets_changed`, `models_changed`, `datasets_changed`, `projects_changed` | `ids` |
| `experiments_changed` | `names` (`<engine>/<name>`) |
| `train_metrics` | `experiment`, `stage`, `points` (training losses) |
| `engines_changed` | `engines` |
| `runtime_changed` | `runtime`: the torch version, the loaded models and the engines' state (as `GET /runtime`) |
| `compute_changed` | `usage`: devices and memory |
| `settings_changed` | `keys`: the settings that changed |

```python
import socketio  # pip install "python-socketio[client]"

sio = socketio.Client()

@sio.on("job_updated")
def on_job(data):
    job = data["job"]
    print(job["id"], job["state"], job["progress"])

sio.connect("http://127.0.0.1:7869", socketio_path="/ws/socket.io", auth={"token": "<token>"})
sio.wait()
```

## Streaming synthesis

### WebSocket: `/api/v1/tts/stream`

Hear the audio as it is made. The protocol:

1. The client sends one JSON text message: a `SpeakRequest`.
2. The server answers `{"type": "queued", "job_id": …}`.
3. When generation starts: `{"type": "start", "job_id": …, "sample_rate": 24000, "granularity": "token" | "segment" | "emulated"}`.
4. Then binary messages: mono 16-bit little-endian PCM at the `start` rate, with `{"type": "segment", "index": n}` before each segment.
5. Finally `{"type": "end", "job_id": …, "output_ids": […], "output_id": …}` or `{"type": "error", "code", "message", "detail"}`.

A binary message is always audio; everything else is JSON text. The whole audio is still stored as a result (`output_id`). The client may send `{"type": "cancel"}` at any time.

`granularity` says how fine the audio arrives: `token` as the model emits tokens (CosyVoice, VoxCPM, Qwen3-TTS), `segment` once per segment, `emulated` when the model does not stream and Mizuoto splits the text to emulate it.

**Streaming text**: with a model that has **Streaming text** (CosyVoice 2 and 3), set `"text_stream": true`; `text` is only the beginning. Send the rest as `{"type": "text", "text": "…"}` messages and `{"type": "flush"}` after the last. Leaving before the flush cancels the job.

```python
import asyncio, json
import websockets  # pip install websockets

async def main():
    url = "ws://127.0.0.1:7869/api/v1/tts/stream?token=<token>"
    req = {"model": "cosyvoice/cosyvoice2-0.5b", "text": "Heard as it is made.", "voice": "my-voice"}
    pcm = bytearray()
    async with websockets.connect(url) as ws:
        await ws.send(json.dumps(req))
        async for message in ws:
            if isinstance(message, bytes):
                pcm += message           # hand it to a player, or keep it
                continue
            event = json.loads(message)
            if event["type"] == "start":
                rate = event["sample_rate"]
            elif event["type"] in ("end", "error"):
                print(event)
                break
    print(len(pcm) // 2 / rate, "seconds")

asyncio.run(main())
```

### HTTP: `POST /tts/speak?stream=true`

Where a WebSocket is awkward, add `stream=true` to the same request: the response is the audio as it is made (chunked transfer):

| Parameter | Response |
| --- | --- |
| `stream_format=wav` (default) | A WAV of unknown length (PCM16 right after the header) |
| `stream_format=pcm` | Mono 16-bit little-endian PCM, no header |

The `X-Mizuoto-Sample-Rate` header is the rate and `X-Mizuoto-Job` the job (the result is still stored). Streaming text is not available this way.

```bash
curl -sN -H "$AUTH" -H "Content-Type: application/json" \
  "$BASE/api/v1/tts/speak?stream=true" \
  -d '{"model": "qwen3tts/1.7b-custom-voice", "text": "Heard as it is made.", "voice_spec": {"preset": "vivian"}}' \
  | ffplay -nodisp -autoexit -
```

## OpenAI-compatible API

Clients written for OpenAI's speech API work with Mizuoto. The two routes are under `/v1` (not under `/api`; at `<prefix>/v1` with `--api-prefix`) and need the access token too:

| Route | Meaning |
| --- | --- |
| `POST /v1/audio/speech` | Speak `input` and answer with the audio |
| `GET /v1/models` | The installed speech models (not speech recognition), and the aliases in `tts.model_aliases` |

How the fields map:

| Field | In Mizuoto |
| --- | --- |
| `model` | A Mizuoto model id; or an alias from `tts.model_aliases`; otherwise `tts.default_model`; with none of them, 404 |
| `voice` | A library voice (id or slug); or a preset speaker of the model; or one of OpenAI's names (`alloy`, `ash`, `ballad`, `cedar`, `coral`, `echo`, `fable`, `marin`, `nova`, `onyx`, `sage`, `shimmer`, `verse`), which fall back to the model's own voice, or its first preset speaker when it has no voice of its own. Any other name is 404 |
| `instructions` | Used only when the model has **Instructions**; ignored otherwise |
| `speed` | 0.25–4; dropped when the model takes no speed |
| `response_format` | `mp3` (default), `opus` (made as ogg), `aac` (made as m4a), `flac`, `wav`, `pcm` (24 kHz mono 16-bit little-endian, no header) |
| `stream_format` | `audio` with `wav` or `pcm` streams the audio as it is made; `sse` is not supported |

Parameters are lenient here: one the model does not take is dropped rather than refused. Errors take OpenAI's shape, `{"error": {"message", "type", "param", "code"}}`, with Mizuoto's error code as `code`. A successful answer carries `X-Mizuoto-Job` and `X-Mizuoto-Model` headers.

Give the usual names aliases first:

```bash
mizuoto config set tts.model_aliases '{"tts-1": "qwen3tts/1.7b-custom-voice", "tts-1-hd": "cosyvoice/cosyvoice3-0.5b"}'
mizuoto config set tts.default_model qwen3tts/1.7b-custom-voice
```
