这一部分写给想修改 Mizuoto 的人：修 bug、接入新引擎、加一个训练方法、加一个页面或一条 API。它描述代码现在**是什么样**、遵守哪些规则以及为什么，而不是使用方法（使用方法见[使用教程](/docs/guide)和[命令行](/docs/cli)）。

## 以什么为准

- **代码**及其测试：其他任何内容与它们冲突时，以它们为准。
- **本站的开发文档**：实现后的设计、规则及其原因，每个领域一页；[引擎参考](/docs/engines)每个引擎一页（复现了上游的哪些行为、
  有哪些偏差、训练器以及对照结果）。改动某个领域前先读对应页面；设计有变化时同步修改它，中英文都要改。
- **`AGENTS.md`**（仓库根目录，`CLAUDE.md` 指向它）：给贡献者和编码代理的简短工作记录：代码地图、不能破坏的规则、工作流程，
  以及哪一页讲什么。

## 一个环境，一个进程

Mizuoto 0.2 是装进同一个 Python 环境的一个发行包。每个引擎（Qwen3-TTS、F5-TTS、OmniVoice、CosyVoice、GPT-SoVITS、VoxCPM、Fish Speech、IndexTTS，以及内部使用的 Whisper 语音识别）都在 Mizuoto 里基于它自己的运行时实现，**在服务器自己的进程里**运行。没有上游代码，没有 transformers，没有引擎专用环境，也没有 worker 进程。

| 发行包 | 位置 | 内容 |
| --- | --- | --- |
| `mizuoto` | `mizuoto/` | 核心、API、命令行、Web UI（构建产物 `dist/` 随 wheel 发布）、运行时、通用构件，以及所有采用宽松许可证的引擎 |
| `mizuoto-fishspeech` | `packages/native/fishspeech/` | Fish Speech，采用 Fish Audio Research License |
| `mizuoto-indextts` | `packages/native/indextts/` | IndexTTS，采用 bilibili Model Use License |

两个需要接受许可的引擎单独发布，只是因为它们的许可证。它们装进同一个环境，通过 Python 入口点组 `mizuoto.engines` 自行注册。

决定代码放在哪里的边界如今在包内部：**`mizuoto/core` 从不在模块顶层导入 torch**，`mizuoto/core/inference` 是它通往模型代码（`mizuoto.runtime`、`mizuoto.nn`、`mizuoto.engines`、`mizuoto.training`）的唯一入口，并且总在函数内部导入。所以 `mizuoto version`、`mizuoto --help` 和核心自己的测试都不加载 torch，一条从不加载模型的命令也从不导入运行时。[整体架构](/docs/development-architecture)就从这条规则讲起。

## 几条贯穿全局的约定

简要列出（完整内容见[开发约定](/docs/development-conventions)）：


- Python ≥ 3.10；ruff 与 ty 不锁版本，`lint.select` 逐条写出；行宽 180；每个函数都有类型标注（测试和脚本除外）。
- 跨越 API 边界的模型都继承 `mizuoto/core/record.py` 的 `Record`（pydantic v2，`json_schema_serialization_defaults_required`）。
- 重依赖在函数内导入；有类注解里用到 `list[...]` 的类不定义名为 `list` 的方法。
- 原生代码不改动任何进程级状态：随机数来自请求自己的生成器（见[运行时](/docs/development-runtime#全局状态)）。
- 新增一个 CLI 命令要同时登记到 `tests/cli/test_cli.py` 的 `EXPECTED_TREE`。
- 只有用户要求时才提交和开 PR。
